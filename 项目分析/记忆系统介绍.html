记忆系统全景概览
记忆系统是智能体的"长期大脑"，负责在对话上下文被裁剪后仍能恢复关键信息，让智能体记住用户偏好、历史操作和项目状态。

🎯 核心设计目标

  • 对话上下文裁剪后仍能恢复关键信息，避免"失忆"
  • 区分临时性记录与永久性知识，自动遗忘过时信息
  • 支持多用户、多会话的记忆隔离与共享
  • 实时记录每一轮对话，即使 LLM 蒸馏未运行也不丢失
  • 通过 Deep Dream 定期提炼长期记忆，保持精炼

📐 设计原则

  • 分层记忆 — 实时层（JSONL）→ 日记层（MD）→ 长期层（MEMORY.md）
  • 时间衰减 — 日期型记忆按半衰期 30 天指数衰减，非日期型"常青"
  • 增量同步 — 基于文件内容哈希判断变更，跳过未修改文件
  • 混合检索 — 向量余弦(0.7) + 关键词 FTS5(0.3) 双路融合
  • 异步刷写 — LLM 摘要在后台线程执行，不阻塞主回复流

记忆更新机制总览
智能体通过 4 种核心机制更新记忆，覆盖从实时记录到深度蒸馏的完整链路。

⚡ 实时记录（无 LLM）

RealtimeMemoryRecorder 在每轮对话后立即写入，不调用 LLM，确保重启后也能恢复近期操作。同时更新用户画像和进程/会话索引。

确定性 零延迟 JSONL 追加

📝 上下文刷写（LLM 摘要）

当对话上下文被裁剪或溢出时，MemoryFlushManager 在后台线程调用 LLM 生成事件维度摘要，追加到当日日记文件。支持去重和上下文注入回调。

异步后台 LLM 摘要 去重保护

🌙 Deep Dream 蒸馏

定期将近期日记与现有 MEMORY.md 一起送入 LLM，执行合并提炼、新增萃取、冲突更新、清理冗余，输出精炼的长期记忆和梦境日记。

深度蒸馏 ≤50 条 冲突解决

📁 文件同步（增量索引）

MemoryManager.sync() 扫描所有记忆文件，基于 SHA-256 哈希判断变更，对修改过的文件重新分块、生成 Embedding、更新 SQLite 索引和 FTS5 全文索引。

增量同步 哈希去重 向量+FTS5

上下文刷写详解
MemoryFlushManager 是记忆从"短期对话"转化为"长期记录"的关键桥梁。

🔴 三种触发场景

✂️

上下文裁剪 (trim)

对话消息超过 token 上限时，_trim_messages 丢弃旧轮次，触发刷写

💥

上下文溢出 (overflow)

API 请求因 token 超限被拒绝时，紧急刷写后清空上下文

🕐

每日定时 (daily_summary)

定时器触发，对当天未刷写的内容生成日终摘要

🛡️ 去重与过滤机制

🔒

内容哈希去重

对每条消息计算 MD5，已刷写过的内容不再重复处理

🚫

调度器消息剥离

自动识别并跳过 [SCHEDULED] 标记的定时任务消息，避免低价值日志

✅

LLM 质量过滤

LLM 判定内容无价值时返回"无"，跳过写入，避免垃圾记忆

Deep Dream 深度蒸馏
Deep Dream 是记忆系统的"睡眠整理"机制，模拟人脑在睡眠中巩固记忆的过程。

🔬 蒸馏六大操作

⊕

合并提炼

含义相近的多条合并为一条高密度表述

✨

新增萃取

从日记中提取值得永久记住的新信息

🔄

冲突更新

新信息与旧条目矛盾时，以新信息为准

🗑️

清理无效

删除临时性记录、空白条目、格式残留

✂️

删除冗余

已被更精炼表述涵盖的旧条目删除

📊

结构分组

用 ## 标题对相关条目分组，保持清晰

🛡️ 安全保护机制

🔒

输入哈希去重

基于 {date}:{daily_hash} 去重，同一天相同内容不重复蒸馏

🚫

空日记保护

近期无日记记录时跳过蒸馏，保留现有 MEMORY.md 不被覆盖

✅

输出验证

LLM 输出无 [MEMORY] 部分时跳过覆写，防止空内容覆盖

📏

Token 自适应

max_tokens 根据输入长度动态调整 (2000~8000)，避免截断

🔧

手动触发

支持 force=True 跳过去重检查，用于 /memory dream 命令

实时记忆记录
RealtimeMemoryRecorder 是确定性、零 LLM 依赖的实时记录器，保证每轮对话都被持久化。

⚙️ 进程记忆生命周期

▶

start_process()

任务启动时创建进程记录，写入初始事件和用户请求

↻

update_process()

任务执行中追加事件（tool_call / phase_change / info），保留最近 80 条

■

finish_process()

任务完成时写入最终响应和状态，同时触发用户画像更新

📝

双格式输出

同时写入 JSON（结构化数据）和 Markdown（可读摘要 + 索引）

📥

record_messages()

📋

_write_recent_state()

同步更新最近 20 条事件的 Markdown 摘要和会话索引

🗜️

自动压缩

事件超过 80 条时，旧事件归入 _summary.md，JSONL 只保留最近 30 条

👤

画像联动

每次记录后同步更新 user_profile.json，提取偏好/目标/关注点

用户画像构建
从对话中持续提取用户持久信息，支持规则匹配实时提取和 LLM 异步蒸馏双模式。

📊 画像数据结构

🔍 双模式提取

⚡

规则匹配（实时）

正则匹配"我希望/需要/想要"、"不要/避免"、"偏好/喜欢"、"目标是"等模式，即时写入画像

LLM 蒸馏（异步）

进程完成后异步调用 LLM，从完整对话中提取稳定的 preferences/goals/projects/facts，合并到画像

🔄

📝

混合检索引擎
MemoryManager 实现向量 + 关键词双路融合检索，并应用时间衰减排序。

⏳ 时间衰减公式

# 日期型记忆：按半衰期指数衰减 multiplier = exp(-ln2 / half_life × age_days) # half_life = 30 天 # 当天记忆: multiplier = 1.0 # 30天前: multiplier ≈ 0.5 # 60天前: multiplier ≈ 0.25 # 90天前: multiplier ≈ 0.125 # 非日期型文件（MEMORY.md 等）: multiplier = 1.0 # → "常青"内容，永不过期

🔤 CJK 检索策略

1️⃣

FTS5 优先

英文和分词语言优先使用 FTS5 全文搜索，BM25 排名

2️⃣

LIKE 回退

查询含中文时自动切换到 LIKE 搜索，提取 2+ 字符的中文词

3️⃣

自动降级

FTS5 不可用时完全回退到 LIKE，确保功能可用

记忆生命周期
一条信息从产生到被遗忘或永久记住的完整旅程。
1

💬 对话产生 → 实时记录

用户每轮对话被 RealtimeMemoryRecorder 即时写入 sessions/{id}.jsonl，同时更新进程记忆和用户画像。这一步无 LLM 调用，零延迟。

2

✂️ 上下文裁剪 → 触发刷写

当对话 token 超限时，旧消息被裁剪。MemoryFlushManager 在后台线程调用 LLM 生成事件维度摘要，追加到 memory/YYYY-MM-DD.md。同时通过回调将摘要注入活跃上下文，保持对话连续性。

3

📁 文件同步 → 索引入库

MemoryManager.sync() 扫描所有记忆文件（MEMORY.md、日记、知识库、教材状态），基于 SHA-256 哈希增量同步变更文件，分块后生成 Embedding 向量，存入 SQLite + FTS5 索引。

4

🌙 Deep Dream → 长期蒸馏

定期将近期日记与 MEMORY.md 送入 LLM 蒸馏。合并相近条目、萃取新信息、解决冲突、清理冗余，输出精炼的 ≤50 条长期记忆。同时生成梦境日记记录整理过程。

5

🔍 检索召回 → 上下文注入

智能体通过 memory_search 工具检索相关记忆。向量+关键词双路融合，时间衰减排序，返回 Top-K 结果。关键记忆被注入系统提示词，让智能体"想起"历史信息。

6

⏳ 时间衰减 → 自然遗忘

日期型记忆按 30 天半衰期指数衰减，90 天后得分降至 12.5%。非日期型"常青"记忆永不过期。过旧的会话记录（>30天）由 ConversationStore 自动清理。记忆自然地从"短期"过渡到"长期"或被"遗忘"。
