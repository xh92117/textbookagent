✂️ _clip() 截断机制

每个分区内容超限时，由 _clip(text, budget_key) 按字符预算截断，追加 ...[已按上下文预算截断] 标记。

💡 节约效果

一本 10 章教材的大纲可能超过 10,000 字符，但骨架提取后仅保留标题行和关键列表项，通常压缩到 2,000 字符以内，节约约 2,700 tokens。

系统提示词构建
PromptBuilder 按 7 个优先级顺序组装系统提示词，每个分区都有 Token 节约设计。

📋 七层提示词注入顺序

优先级分区注入内容Token 节约策略
1工具系统工具名+一句话摘要不注入完整 schema，仅列名称和简述
2技能系统技能描述+SKILL.md 路径按需读取，不预加载 SKILL.md 全文
3记忆系统检索指引+文件结构说明MEMORY.md 已在上下文中，无需重复检索
3.5知识系统knowledge/index.md 索引仅注入索引，详情用 read 按需读取
4工作空间路径规则+已加载文件清单标注已加载文件，避免重复 read
5用户身份姓名/时区/备注仅 3-5 行，极简注入
6项目上下文AGENT.md + USER.md + RULE.md + MEMORY.md一次加载，标注"已加载，无需再读"
7运行时信息时间/模型/工作状态动态时间（可调用），工作状态精简摘要

🧩 技能按需加载

技能系统不预加载 SKILL.md 全文，仅在提示词中注入技能的 <description> 和 <location>。智能体匹配到技能后才用 read 工具读取。

💡 节约效果

假设 10 个技能，每个 SKILL.md 平均 800 字符。按需加载避免注入 8,000 字符（≈2,700 tokens），实际仅注入约 1,000 字符的描述列表。

📚 知识索引注入

知识系统仅注入 knowledge/index.md 的索引内容，不注入知识页面全文。智能体需要详情时用 read 或 memory_search 按需获取。

💡 节约效果

知识库可能有 50+ 页面，每页平均 2,000 字符。仅注入索引节约约 100,000 字符（≈33,000 tokens），代价仅约 500 字符的索引列表。

上下文包构建
ContextPackageBuilder 为教材编写场景定制，从大纲到术语表，每个分区都有精炼提取逻辑。

✂️ 精炼提取手法

🦴

大纲骨架化

正则过滤仅保留 #~#### 标题行和"教学目标/核心概念/需要图表"列表项，丢弃所有正文

🎯

章节精准切出

正则匹配"第X章"标题位置，只提取当前章的完整大纲，其他章节不注入

📝

小结优先摘录

优先使用"本章小结"段落（≤360 chars），无小结时取尾段 260 chars 摘录

🗑️

代码块替换

代码块自动替换为 [代码示例略]，节约大量 token

启动时紧凑注入
MemoryBootstrap 在会话启动时一次性注入紧凑记忆包，避免逐文件读取的 token 开销。

📋 启动注入内容

👤

用户画像

读取 user_profile.md 头部 1,200 字符，包含偏好、目标、项目

⚙️

近期进程索引

最近 8 个进程记忆的标题+路径，不含正文（按需 read）

⚠️

错误记忆索引

最近 6 个错误记录的标题+路径，避免重复犯错

📚

教材状态索引

最多 12 本教材的标题+状态路径，不含完整状态数据

💡 节约效果

仅注入索引而非全文。智能体需要详情时用 read 按需获取。假设 8 个进程各 2,000 字符，仅注入约 400 字符的索引，节约约 5,000 tokens。

📋 工作状态注入

WorkStateManager 将当前工作状态精简摘要注入运行时信息：

# 注入示例（约 200 字符） 当前教材: 结构力学 (ID: structural_mechanics) 已完成阶段: outline, research, chapter_1, chapter_2 进行中阶段: chapter_3 最近工具调用: read(ch3.md):success, write(ch3.md):success 状态更新时间: 2026-05-20T14:30:00

💡 节约效果

完整工作状态 JSON 可能超过 5,000 字符，精简摘要仅约 200 字符，节约约 1,600 tokens。同时避免智能体重复执行已完成的步骤。

上下文裁剪与记忆刷写
当渐进压缩仍不够时，裁剪最旧轮次并刷写到记忆系统，同时注入摘要保持连续性。

🎯 Token 预算计算

# _effective_context_budget() 核心逻辑 context_window = _get_model_context_window() # 如 Claude=200K, GPT-4=128K reserve = _get_context_reserve_tokens() # 为输出和工具增长预留 hard_cap = max(1024, context_window - reserve) # 用户配置的上限会被 clamp 到 hard_cap max_allowed = min(user_configured, hard_cap) # 实际可用 = max_allowed - system_prompt_tokens available = max_allowed - estimate_tokens(system_prompt)

💡 关键设计

用户配置的 max_context_tokens 被视为"请求上限"而非"真实值"，最终预算始终被模型窗口和预留空间 clamp。这防止了超大配置绕过裁剪，发送百万级 Token 的提示词。

上下文状态板
build_context_state_board() 在裁剪后注入紧凑操作记忆，让智能体知道"已做过什么、该做什么"。

📋 状态板内容结构

[System: Current task state board] This compact state survives context compression and is the authority for task progress. Do not restart completed steps. Current user goal: 编写第三章结构分析 Recent decisions/progress: - 已确定章节框架包含4个小节 - 已收集12篇参考文献 Already read/available files: - READ file: ch2_summary.md | memory/... - READ file: outline.md | textbooks/... Knowledge/source saves: - SAVED knowledge: 结构力学基本原理 | url Failures to avoid repeating: - FAILED web_fetch: 403 Forbidden | url Written outputs: - WROTE file: textbooks/struct_mech/ch3.md Loop guard: if an action appears under read/saved/written/progress/failures, treat it as already attempted. Next-step rule: if enough chapter evidence has been gathered, write/save the chapter instead of searching again.

🎯 状态板 Token 节约逻辑

📊

事件精简摘要

每个工具调用压缩为一行：READ/WROTE/SAVED/FAILED + 关键信息，最多 36 个事件

🔄

去重保序

_dedupe_keep_order() 确保相同事件不重复列出，保持时间顺序

🚫

循环防护

"Loop guard"指令防止智能体重复执行已完成的搜索/读取步骤

➡️

下一步引导

"Next-step rule"指令引导智能体从当前进度继续，而非重新规划

💡 节约效果

10 轮对话的完整历史约 15,000 tokens。状态板约 500 tokens，节约约 14,500 tokens（97%），同时保留了操作连续性。
