协作架构全景
PipelineRunner 是教材编制的中枢调度器，编排 6 个子智能体按 7 阶段管线顺序执行，每章经历 9 个确定性动作。
🤖
六大子智能体
每个子智能体继承 TextbookBaseAgent，拥有独立的系统提示词、用户提示词模板和输出解析器。
📋

OutlinerAgent

outliner

大纲编制智能体。基于 OKR 递归分解和布鲁姆认知层次，从教材目标逐级分解到章节要点，生成结构化大纲。

OKR 分解 布鲁姆标注 术语表初始化
🔧

ComposerAgent

composer

上下文组装智能体。收集大纲、前章摘要、术语表、当前状态，组装为低 Token 写作上下文包。

上下文组装 预算控制
✍️

WriterAgent

writer

章节编写智能体。基于上下文包撰写章节正文，自动识别图表/插图需求，输出 VISUAL_ASSETS JSON。

去AI味 图表识别 习题设计
🔍

ReviewerAgent

reviewer

审查评分智能体。双模式审查：大纲审查（8 维度）和章节审查（20 维度），输出评分和问题列表。

双模式 评分+问题 JSON 输出
✏️

ReviserAgent

reviser

修订智能体。根据审查问题列表进行定点修复（spot-fix），仅修改有问题的段落，保留已通过内容。

定点修复 条件触发
✨

PolisherAgent

polisher

润色智能体。统一写作风格、提升可读性、消除残留 AI 痕迹。评分 ≥88 且无严重问题时自动跳过。

风格统一 智能跳过
⚡
四大核心技能
技能由 SKILL.md 定义触发词和指令，智能体匹配后按需读取执行。SkillManager 管理加载、启用/禁用和提示词注入。
📋

textbook-outline

大纲编制技能

触发词匹配后，智能体读取 SKILL.md 获取 OKR 递归分解指令，搜索课标，生成结构化大纲并保存。支持新建和调整大纲。

编制大纲 生成大纲 规划大纲 调整大纲
✍️

textbook-chapter

章节编写技能

触发词匹配后，智能体读取大纲、前章摘要、术语表和去AI味规则，执行知识库+网页证据充实，编写章节正文。

编写第 写第 续写章节 重写章节
📚

knowledge-organizer

知识库整理技能

触发词匹配后，执行 organize.py 脚本对知识库进行 AI 整理，提取知识条目、建立关联图谱、生成交叉引用。

整理知识库 梳理知识
📖

textbook-fullbook

全教材一键生成技能

触发词匹配后，展示参数确认表格，用户确认后调用 start_pipeline 工具启动 7 阶段管线，支持暂停/恢复/取消。

编写教材 一键生成 整本教材 制作教材

📂

加载扫描

🔄

教材编制管线（从零到成书）
7 阶段管线从用户需求出发，自动编排子智能体和技能，逐章推进直到整本教材完成。
🎼
ChapterOrchestrator 编排器
确定性动作规划器，为每章生成 9 个动作序列。默认全为 required=True，revise 和 polish 根据审查结果条件跳过。

📋 9 个确定性动作

#动作子智能体/模块条件
1read_outlineContextPackageBuilder必执行
2retrieve_knowledgeKnowledgeRetriever有知识库时
3build_contextContextPackageBuilder必执行
4write_chapterWriterAgent必执行
5route_visual_assetsVisualAssetRouter必执行
6review_chapterReviewerAgent必执行
7revise_chapterReviserAgent评分<80时
8polish_chapterPolisherAgent评分<88或有严重问题
9persist_chapterChapterPersistence必执行

🎯 条件跳过逻辑

✏️

revise_chapter 条件触发

审查评分 ≥80 分时跳过修订，标记 "review score passed"，节约一次 LLM 调用

✨

polish_chapter 智能跳过

评分 ≥88 且无 critical/warning 问题时跳过润色；短章节（<1200字）评分 ≥82 也可跳过

📚

retrieve_knowledge 可选

has_knowledge=False 时标记为非必需，无知识库时自动跳过检索

📊

预算自适应

chapter_word_count ≤3000 时上下文预算 ×0.85，≥8000 时 ×1.15

💾
检查点与断点续传
PipelineCheckpointStore 为每章保存动作状态，支持断点续传和暂停/恢复/取消。

📋 检查点文件结构

# state/pipeline_checkpoints/chapter_01.json { "chapter_number": 1, "updated_at": "2026-05-20T14:30:00", "actions": [ { "name": "read_outline", "status": "completed", "output_summary": "outline loaded" }, { "name": "write_chapter", "status": "running", "started_at": 1716191400.0 } ], "extra": {"stage": "write_chapter"} }

🎮 管线控制

⏸

pause() 暂停

设置 _paused 标志，当前动作完成后在 _check_pause_cancel 处挂起

▶

resume() 恢复

清除 _paused 标志，管线从挂起点继续执行

⏹

cancel() 取消

设置 _cancelled 标志 + cancel_event，所有子智能体收到取消信号

🔄

断点续传

resume_from 参数指定起始阶段，已完成的章节自动跳过（scheduler.mark_completed）
